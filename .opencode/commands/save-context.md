Ты должен дописать **новую секцию** в файл `project-ai/session-log.md` с
суммой текущей сессии. Не перезаписывай файл, не трогай существующие
секции. Если файла нет — создай его с заголовком `# Session log` и затем
добавь первую секцию.

## Контекст для извлечения данных

Текущая дата и время:
!`date -u +"%Y-%m-%d %H:%M UTC"`

Текущая ветка и последний коммит:
!`git rev-parse --abbrev-ref HEAD && git log -1 --oneline`

Файлы, изменённые относительно HEAD за время сессии (рабочее дерево):
!`git status --porcelain`

Краткий diffstat:
!`git diff --stat HEAD`

## Что записать

Добавь в конец `project-ai/session-log.md` новую секцию строго по этому
шаблону. Заполняй её на основе **всей текущей сессии** (твой разговор с
пользователем и сделанные тобой правки), а не только последнего сообщения.

```markdown
---

## <ISO-дата из вывода `date` выше> — <короткий заголовок сессии, 3–7 слов>

**Ветка:** <branch>
**Базовый коммит:** <hash + subject>

### Что обсуждали / какую задачу решали

<2–5 предложений по существу. Не пересказывай реплики, формулируй задачу
и принятый подход.>

### Что сделано

- <маркеры: правки кода, новые файлы, удаления; для каждого — путь и в
  одну строку зачем>

### Принятые решения

- <архитектурные/продуктовые решения, которые стоит помнить в будущих
  сессиях. Если решений не было — пиши "—".>

### Открытые вопросы / TODO

- <что осталось недоделанным, что нужно решить, на что обратить внимание
  в следующий раз. Если нет — "—".>

### Затронутые файлы

<маркированный список путей из `git status` и `git diff --stat`. Если
пусто — "—".>
```

## Правила

- Пиши на русском, в стиле существующих документов в `project-ai/`.
- **Не** изобретай факты. Если чего-то не было в сессии — ставь `—`.
- **Не** дублируй правила из `AGENTS.md` и `project-ai/*.md` — это
  журнал событий, а не контракт.
- **Не** трогай `AGENTS.md` и другие файлы в `project-ai/`, кроме
  `session-log.md`.
- **Не** запускай `npm run check`, `git add`, `git commit` или другие
  команды модификации репо. Команда только пишет в один файл.
- В заголовке секции используй именно ту дату/время, которые вернул
  `date` выше, не подставляй другую.
- После записи коротко отчитайся пользователю: одна строка с путём к
  файлу и числом добавленных пунктов.
